# 第56章 管理员没有退出

服务商把三种方案发来时，已经晚上九点四十。

第一种，冻结协管账号令牌。

优点是可以立即阻止现有登录设备继续访问；不删除历史管理员关系，便于固定后续核验。风险是对方可能收到会话失效提示，意识到权限正在被处理。

第二种，彻底删除协管角色。

可以从服务端解除权限，但操作会改变后台状态，需在删除前完成完整记录；部分日志可能进入归档流程，调取时间变长。

第三种，不再启用原手表，保留封存状态，同时为小禾建立全新设备与独立账号。旧协管账号短期仍存在，但因设备离线无法读取实时位置。若原设备意外开机联网，风险重新出现。

三种方案可以组合。

最稳妥的技术选择似乎是立即冻结、完整取证、删除旧权限、永久停用手表，再换一套新设备。

陆衍已经把执行顺序排到第五步。

他拿起电话前停住。

“先问许棠。”

不是林栀提醒。

是他自己说。

私人身份回合仍停在“轮到你”，蓝色筹码还压在餐桌。两个人没有把它收起来，只让它留在原处，明确私人问题并未消失，只是暂时没有优先权。

林栀联系接待点。

许棠还没睡，小禾已经入睡。她同意现在听方案，但要求不要叫醒孩子。

“旧手表开着吗？”林栀先问。

“关机，封袋还在我柜子里。”

“封条有没有变化？”

“没有。”

“那当前没有设备上线，实时位置风险相对受控。后台权限仍在是重要问题，但你可以在理解选项后决定，不需要因为我们深夜来电立刻选全部。”

许棠听完三种方案，问：“冻结以后，他会知道吗？”

“可能只看到登录失效，也可能收到账号安全提示，具体取决于服务设置。”周屿远程加入，“我们不能保证对方没有反应。”

“删除以后，证据会没吗？”

“删除前完成固定，现有证据不会因为页面变化自动消失。但服务商后续调取流程可能变化，所以要先取得确认。”

“换新手表，是不是又要把小禾的位置交给另一个平台？”

“可以选择普通非联网手表，也可以使用新智能设备但关闭非必要权限。联系、定位和紧急功能各有取舍。”

“如果不用智能手表，她在学校找不到我怎么办？”

“学校有独立紧急联系卡和教师渠道。是否足够，由你结合小禾使用习惯决定。”

陆衍把自己拟好的五步方案放在一旁。

“你理解每一步可能的后果吗？”他问。

“大致理解。冻结是先让那个账号不能再看；删除要等证据固定；换设备是另一件事。”

“对。你愿意怎么处理？”

许棠想了很久。

“今晚先冻结。”她说，“完整记录由你们和服务商保存。旧手表不再给小禾戴，但先不删除管理员，我想等法院和执行报告需要的材料都确认。新设备先不用智能的，给她普通表和学校联系卡。”

“是否授权服务商现在冻结协管账号全部访问令牌？”

“授权。”

“是否授权固定冻结前后状态、通知记录和设备标识？”

“授权。”

“是否同意对方可能收到提示的风险？”

许棠吸了一口气：“同意。入口继续加强，如果他有新动作，我按执行卡处理。”

决定完成。

陆衍才把任务发给服务商。

不是技术最彻底的一次清除，却与许棠的证据需求、孩子使用习惯和现实风险相匹配。

十点零三分，冻结开始。

周屿通过屏幕见证服务商操作。变更前页面显示协管账号存在一个活动令牌、一个三十日未使用令牌；两者设备标识不同。服务商先导出权限与会话状态，生成记录，再执行冻结。

活动令牌失效。

后台管理员角色仍在，但所有访问状态变成“已冻结”。

“这次真的不能看了吗？”许棠问。

“在现有服务范围内，令牌已失效，设备也保持离线。”周屿说，“仍需检查有没有其他共享账户和新授权，不能说所有数字路径从此绝对关闭。”

“至少这一个关了。”

“对，这一个关了。”

许棠长长呼出一口气。

没有人用“终于安全”替代准确答案。

十点十五分，服务商完成操作说明。林栀把结果记入执行表，同时更新学校与紧急联络方案。

后台权限问题不只存在于儿童手表。

错峰十分钟的放学时间，曾通过校方新系统发送到许棠独立账号。系统后台沿用旧学生档案中的第二监护联系人，虽页面显示抄送失败，实际邮件服务器日志仍需核验。

“明天先暂停小禾课程？”陆衍问。

“许棠已经选了暂停一天。”林栀说，“后天是否恢复要重新问。”

“学校联系人全部换成独立号码，旧家校平台停用。”

他语速很快，像又要直接形成命令。

停了半秒，改口：“这是建议。许棠，你是否愿意同步更换学校交接和紧急联络方式？后果是宋恺不能通过旧平台接收日常通知，但涉及孩子的必要事项要走指定渠道，可能增加沟通时间。”

“愿意。”

“是否保留孩子祖母为紧急联系人？”

许棠犹豫。

祖母参与送花，知道错峰放学时间；可她也曾在小禾生病时照顾多年，是孩子熟悉的人。直接删除，会让许棠少一个紧急支持，也可能让小禾觉得整个父系家庭同时消失。

“我不想她继续看到位置和接送时间。”许棠说，“但如果小禾在学校真的出事，我希望联系不上我时能通知她。”

林栀提出拆分权限：祖母不进入日常课程、位置和接送系统，只作为第三顺位紧急联络人；联系时由学校说明健康或安全事项，不提供现居地址和路线。任何接走孩子仍需许棠明确确认。

“可以。”许棠说。

这比一键删除复杂。

却更接近她真实想要的边界：限制信息，不抹去全部亲情。

校方负责人在电话里确认修改。主联系人是许棠独立号码；第二联系人改为接待点指定联络；祖母降为第三顺位，只在前两者均无法联系的紧急情况下使用。宋恺不再出现在普通接送名单，必要亲职事务走文书指定渠道。

“系统能保证不自动抄送旧联系人吗？”周屿问。

“页面可以取消。”校方说。

“需要后台日志确认。前台取消不等于服务端规则已经删除。”

同一个教训不能只在手表上学一次。

学校联系平台由第三方公司维护。技术人员检查后发现，旧第二监护人字段已经在界面隐藏，通知规则却有一条历史自动化任务，条件是“课程时间变更时抄送所有原监护联系人”。

这条任务没有随界面编辑自动删除。

错峰十分钟的通知曾经触发它。

系统显示一封邮件发往宋恺旧登记邮箱，状态先为“排队”，随后因邮箱转发规则而显示“原地址投递失败”。平台此前只把最后状态解释成抄送失败。

“转发去了哪里？”林栀问。

“需要邮件服务商日志。”技术人员说，“我们只能看到原邮箱设置了自动转发，目标地址被脱敏。”

“什么时候设置？”

“两年前。不是这次临时新增。”

信息路径开始出现。

课程变更通知进入宋恺旧邮箱，再按既有规则转发。谁能访问转发目标、祖母如何得到时间，仍未闭合，但校方不是有人临时把消息告诉宋恺，系统遗留规则本身已经把边界绕开。

许棠听完，声音发冷：“我每次改联系人，他们都告诉我改好了。”

“页面确实改了。”林栀说，“问题是后台历史任务没有同步。我们会保留变更记录和技术说明。”

“那以后我怎么相信任何一个‘已删除’？”

没有人能给她一个所有系统永不出错的保证。

周屿提出验证清单：前台成员、后台角色、自动化任务、转发规则、活动会话分别检查；变更以后用不含真实地址的测试信息确认旧渠道不再收到，再逐步恢复实际使用。

“我愿意按这个做。”许棠说。

测试不能使用小禾真实的课程、教室和接送地点。

沈念临时拟了一条无意义通知：“周四美术材料由彩纸改为白纸，请主联系人确认。”校方把测试学生编号替换成一串独立字符，只保留与小禾相同的通知规则。许棠的独立号码收到短信，接待点指定联络收到第二顺位提醒，祖母的号码没有收到日常通知。

第一轮看上去正常。

周屿却没有在结果栏打勾。

他让技术人员查看发送队列，而不是只看手机有没有响。队列里果然还有一条灰色记录，收件目标被标记为“历史监护组”，状态是规则停用，因此未生成邮件。

“这条灰色记录还会保留多久？”

“历史任务清理以后就不会再生成。”

“清理是删除任务，还是只把启用值改成零？”

技术人员沉默了几秒，重新打开管理端：“只改成零。任务定义还在。”

“那请把定义、停用时间、操作者和当前状态一起导出。暂时不删除，先写入整改说明。后续若删除，再单独形成变更记录。”

陆衍看了周屿一眼。

前台解绑，后台角色还在；页面取消，自动任务还在；手机没有收到，不代表发送队列从未尝试。几个系统像把同一句话用不同方式重复给他们听：看不见，不等于不存在。

林栀忽然明白许棠为什么会在每一次“已经处理”之后变得更不安。

外人很容易把那种反复确认叫作多疑。许棠会问门锁三次，问司机姓名两次，到了接待点仍要检查窗帘后面。若只看动作，她像是在让所有人陪她完成永远没有终点的验证；可真正没有终点的，从来不是她的问题，而是那些被做成默认项、历史项、自动项的权限。每当她鼓起勇气切断一个可见入口，系统便替控制者保留一条她不知道的旧路。

这也是“替她一次性全部删掉”最诱人的地方。

律师会获得一种干净利落的成就感，技术清单上全是绿色，今晚似乎就能结案。可许棠明明说过，她要保留祖母作为第三顺位紧急联系人，也要先固定管理员证据。若他们为了彻底而忽略这些选择，做法或许更有效率，本质上却仍是另一个人自信地告诉她：你不必理解，我替你决定。

林栀在执行表旁新增一栏，不叫“已处理”，改叫“当事人选择与保留项”。

祖母的第三顺位、旧手表的封存、协管角色暂不删除，都写进去。每项后面再列触发复核的条件：接到异常通知、新设备登录、校方变更课程、接送人员临时调整。

陆衍看见表头，低声说：“这个模板以后保留。”

“只保留字段，不复制选择。”

“知道。下一位当事人重新问。”

他回答得很快，没有为自己的建议争辩，也没有把一次及时改口当成值得记分的进步。

林栀视线从表格移到屏幕角落。那里还压着私人回合的计时提醒，早已因客户电话自动暂停。控制和照顾之间最危险的区别，有时并不在方案本身，而在谁有权按下确认。她与陆衍把这一点写进三行公约，是因为他们有余裕把界限做成游戏；许棠没有。许棠必须在真正的风险里，一次次把确认权夺回来。

十一点，学校旧自动任务停用，变更前后记录保存。所有接送名单重新生成，校方负责人逐项确认，没有把孩子家庭情况发进普通教师群。

林栀问许棠：“今晚还需要我们做什么？”

“我想睡觉。”

“好。非紧急更新明早再说。”

“男朋友那个热榜……”许棠忽然提起。

林栀停了一下。

“我看见一点。”许棠说，“你们不用因为我的事一直停下自己的生活。”

“停战是我们自己的规则，不是你欠我们的成本。”

“但你们也会累。”

“会，所以团队轮值。客户不需要用关心律师私生活换取服务。”

许棠轻轻笑了一声：“好，那我不问。”

通话结束。

林栀看向餐桌。

蓝色筹码仍在那里，旁边那张虚假否认声明被两只杯子压着。

“继续刚才的问题？”陆衍问。

“现在十一点，服务商和学校刚完成变更。”

“所以？”

“客户紧急状态今晚仍然冻结。”

“同意。”

他没有用许棠那句“不用停下生活”要求恢复。

林栀拿起那枚蓝色筹码，本想放回盒里，指尖碰到边缘又停住。

“放着吧。”陆衍说。

“你不怕明早有人来，看见以后问这是什么？”

“可以说是暂停标记。”

“然后他们会问，暂停什么。”

“那就不回答。”

他说得理所当然，仿佛拒绝解释比给关系命名容易得多。

林栀把筹码放回原位。红灯没有亮，录音设备也没有被取出。那张否认声明仍被两只杯子压着，纸边因水汽略微卷起，“共同生活”四个字却没有被遮住。

他们今晚至少完成了另一种确认：私人问题不会借客户的疲惫偷渡答案，客户也不会被要求为他们的停战承担内疚。

两人收起电脑，确认值班人员接管，准备休息。

午夜前，服务商又发来一份冻结前的完整会话记录。

协管账号在保护措施送达后，不只登录过一次。

最新一条显示，它更换了登录设备。

旧设备标识停用三小时后，一台从未出现过的新设备完成验证，并查看了手表状态页。

管理员没有退出。

它只是在旧入口被发现以后，换了一扇门。
