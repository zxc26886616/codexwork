# 项目规则

这份规则用于保持游戏项目、文档和素材的组织方式一致。更偏执行约束的版本见根目录 `AGENTS.md`。

## 1. 目录规则

```text
codexwork/
  README.md
  AGENTS.md
  docs/
  projects/
```

- `projects/` 放可运行的游戏项目。
- `docs/` 放设计文档、开发规范、素材规范和模板。
- 根目录不直接放游戏源码。

## 2. 新游戏规则

新增一个游戏时，至少创建：

```text
projects/<project-name>/
  README.md
  index.html
  styles.css
  game.js

docs/projects/<中文项目名>.md
```

同时更新：

- 根目录 `README.md`
- `docs/项目总览.md`

## 3. 玩法规则

- 第一版必须能玩，而不是只展示界面。
- 玩家目标要明确。
- 操作方式要简单。
- 必须有反馈，例如分数变化、受击反馈、成功反馈或失败提示。
- 如果有失败条件，失败后必须能重新开始。

## 4. 界面规则

- 默认中文界面。
- 按钮文字要短。
- 分数、生命值、倒计时等核心状态要清楚可见。
- 移动端不能出现明显文字重叠或按钮遮挡。
- 游戏画面优先，不把主要体验藏在说明页后面。

## 5. 技术规则

- 轻量网页小游戏优先使用原生 HTML、CSS、JavaScript。
- 默认不引入复杂框架。
- Canvas 游戏使用 `requestAnimationFrame` 做主循环。
- 碰撞、生成、输入、绘制逻辑尽量分区清晰。
- 重要手感参数要方便调整。

## 6. 文档规则

`docs/` 目录下的 `.md` 文件必须使用中文文件名，例如：

```text
docs/项目总览.md
docs/开发规范.md
docs/projects/信号漂移.md
docs/templates/游戏设计文档模板.md
```

代码项目目录可以继续使用英文 slug，例如 `projects/signal-drift/`。

每个游戏设计文档至少包含：

- 一句话概念
- 核心体验
- 操作方式
- 规则
- 胜负条件
- 主要数值
- 反馈设计
- 后续想法

## 7. 验证规则

修改游戏后至少检查：

```powershell
node --check projects\<project-name>\game.js
```

如果改了界面，还要手动打开对应 `index.html` 看一眼首屏、按钮和游戏画面。
