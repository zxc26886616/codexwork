目标是让助手从 BGA **「开始游戏 → 即时制」** 进入《海盐折纸》，由平台自动匹配在线对手。用户启动一次批次，助手负责排队、接受匹配（页面要求时）、操作己方座位、收录官方结算，再回到即时制入口排下一局。批次配置只需知道己方账号、游戏偏好和截止时间，对手身份在平台分桌后读取。[BGA 游戏大厅说明](https://en.boardgamearena.com/faq)

### 第一步 从即时制大厅自动进入第一桌

1. 在目标大厅确认「开始游戏」、即时制、自动匹配对手和《海盐折纸》的实际入口。用现有 `list`、`inspect` 记录可见状态，再在 `app/lobby.js` 中增加识别。首轮验收沿用已支持的基础版双人范围，入队前核对平台可用的偏好设置。若队列不能保证该规则范围，先验证可能分到的桌型，再开放线上长测。
2. 为 `control/SeriesRunner.cs` 增加即时制批次分支，与现有 `HotseatLobby` 分开调度。排队请求只发一次，收到官方队列状态后持续等待。平台直接分桌时进入游戏。如要求确认，在确认窗口有效、模式匹配且批次未截止时接受一次。
3. 从平台分配的桌读取站点、桌号、游戏、己方玩家 ID、公开席位和规则。确认本人已入座且有对应手牌后，复用 `app/Desk.cs` 的普通桌出牌循环。观战、回放或热座视图不启动。对手 ID 随本桌保存，下一桌重新读取。

**验收**　从未入队的大厅开始，一次启动后自动进入第一张即时制桌并完成官方结算。日志能逐步定位入队、分桌、己方首次行动和结算。整条路径无需输入桌号、对手昵称或对手 ID。

### 第二步 结算后自动排下一局

- 调整 `app/SeriesBook.cs` 的即时制收录逻辑。按站点和桌号定位结果，以己方 ID 及本桌实际席位核对名次和得分。连续两局碰到同一玩家仍按两个桌号计数。旧热座批次保留原有收录方式。
- 收到完整官方结算并原子入库后，清除本桌绑定，回到「开始游戏 → 即时制」，核对游戏和模式后再入队。上一桌的迟到回执不能触发第二次入队。
- 批次到点后停止新匹配。还在队列时请求取消并核实最终状态。若取消与分桌同时发生，以平台已生效的状态为准。已进入的对局正常打完并收录，单列收尾时间。

**验收**　同一批次由平台连续分配至少 3 桌，每桌只操作己方、只收录一次，第二桌和第三桌均由上桌结算自动触发排队。复查批次日志与官方结果，逐桌核对席位、名次和分数。

### 第三步 恢复排队和进行中的对局

普通桌已能等待对手。批次层 `SeriesRunner.Play` 另有四分钟无进展超时，`WriteLog` 会更新进展时间。即时制需分别记录进程心跳、队列状态、当前行动方和最后一次已确认的动作。

| 情形 | 恢复和验收 |
| --- | --- |
| 排队超过四分钟，或匹配确认过期 | 官方仍显示在队时继续等。超时后先判断平台已自动回队、已出队还是已分桌，只在明确出队后按退避规则重排。 |
| 提交入队后断线，或刚分桌进程退出 | 发起排队前保存意向。恢复后先核对平台的在途队列和进行中桌，有桌优先回原桌。状态不明时暂停，避免同时占两桌或重复排队。 |
| 对手长考、掉线或退出 | 对手回合持续等待，己方回合恢复行动。退出、弃权或流局单独记录，按官方结果决定是否结算。 |
| 己方出牌后回执丢失，或战绩落盘后批次中断 | 持久化未确认动作，回原桌核对阶段，不能确认时暂停。复用 `tests/TableScenario.cs` 和 `tests/SeriesBookChecks.cs` 的原桌恢复与去重断言，验证不会重出牌、漏收或多排一局。 |
| 登录失效、验证码、未知页面或磁盘不可写 | 暂停自动操作，保留批次和当前桌，给出可定位原因。人工接管的批次标记为未通过无人值守长测。 |

## 连续 24 小时的验收

使用同一候选版本和批次 ID，从首次向即时制队列发起匹配起连续计满 24 小时。分别统计排队、实际对局、断线和暂停时长。每张有效桌都应能追溯到本批次的匹配记录和独立远端座位。

| 检查时间 | 通过条件 |
| --- | --- |
| 第 2 小时 | 已观察到结算后自动重排，逐桌对账一致。长时间未分桌时，能从日志区分正常排队和客户端卡住。 |
| 第 8 小时 | 跨时段仍能匹配和出牌，无并发队列、重复入桌或错误座位点击。检查心跳、最长等待、内存及日志增长。 |
| 第 24 小时 | 连续运行到点并安全收尾。己方人工代打、手动找桌或重启批次均为零。每张已完成桌与官方结算一致，异常终止桌均有记录。 |

为防止全天空排也被算作实战，沿用已拟定的覆盖指标，24 小时内有效对局累计至少 18 小时，每个两小时窗口都有双方行动。有效时间按局内实际时段扣除可识别的离线和故障暂停。开跑前根据短测冻结覆盖指标与资源预算。如果队列供给不足，报告实际对局数、有效时长和最长排队，分别给出程序稳定性与实战覆盖的结果。

验收记录保存版本、站点、批次 ID、入队及分桌时间、逐桌官方成绩、重新入队次数、恢复耗时和人工介入次数。附第一桌、一次结算后重新匹配和最后一桌的完整事件序列。中途改代码或调整门槛后，使用新批次重新计时。
