# CAD 自动挂机控制台设计文档

## 一句话概念

为 `D:\code\cad-client-mas\cadclient3.0_unity2021\cadclient3.0_unity2021` Unity 项目提供一个独立的本地 Web 控制台，先完成安卓草花账号登录和渠道凭证获取，再连接游戏网关，并逐步扩展到合规挂机任务。

## 核心体验

- 开发者启动本地服务器后，用浏览器查看当前挂机参数。
- Web 界面可以保存自动登录参数，并发起一次自动登录命令。
- Web 界面可以一次性提交草花账号密码，或输入 SDK 已签发的 `userId/token` 做联调。
- 本地服务器调用获授权的草花登录代理，将账号密码换成游戏登录服需要的 `userId/token`。
- 第一阶段完成渠道、登录服、角色服、选角和在线保持闭环，后续再扩展挂机任务。

## 操作方式

- 在 `projects/cad-auto-bot/` 执行 `node server.js`。
- 打开 `http://127.0.0.1:17830`。
- 输入草花账号密码，调整服务器、角色选择、重试等自动登录参数。
- 点击“执行自动登录”。
- Mock 模式只演练参数和命令；正式服模式需要实现 `adapters/officialAdapter.js`。

## 规则

- `D:\code\cad-client-mas` 永久作为只读源码参考，只允许读取渠道配置、任务配置和协议定义；禁止由控制台或实现过程向该目录写文件、生成资源、构建改造版客户端或注入代码。
- 自动挂机工具作为独立项目放在 `D:\code\codexwork\projects\cad-auto-bot`。
- 本地服务器只监听 `127.0.0.1`，默认端口 `17830`。
- 非敏感参数保存到本地 `data/config.json`；玩家密码、草花 token 和 Bot Token 不落盘。
- 不实现客户端外挂、反作弊绕过、验证码绕过、支付绕过或隐蔽输入模拟。
- 正式服执行必须使用白名单账号、bot token、限流和审计日志。

## 自动登录能力

| 项目 | 当前设计 |
| --- | --- |
| 登录模式 | 最近角色、指定角色 ID、指定角色序号、仅账号登录 |
| 参数面板 | Web 表单显示并保存当前自动登录参数 |
| 命令触发 | `POST /api/login/request` 创建自动登录命令 |
| 草花登录 | `POST /api/login/request`，账号密码只随本次请求发送；未进入游戏的渠道 token 最多保留三十分钟 |
| Android sdkParam | 从客户端 `Channel.json` 明确选择渠道，结合登录回调 `extensionJson` 生成；也支持代理直接返回完整值 |
| 执行适配器 | Mock 适配器演练，official 适配器按配置调用获授权的草花登录代理 |
| 登录服握手 | 已实现 WebSocket challenge、DH、HMAC64、DES token 与 200 跳转解析，默认关闭真实连接 |
| 角色网关认证 | 已实现二字节长度包头、重定向 HMAC 认证和长连接保持 |
| Sproto 业务协议 | 链接客户端生成的 `Sproto.cs`，已实现 GateMessage 双层编解码与 DES 收发 |
| 角色登录 | 已实现角色列表、最近角色/指定 ID/指定序号选角和 `Role_RoleLogin` |
| 在线保持 | 每 15 秒发送 `Role_Heart`，收到 `Role_Ping` 自动回复 `Role_Pong`；连续三次失败自动清理连接 |
| 会话生命周期 | 角色登录成功后清除渠道密钥并持续在线；支持 Web 主动断开，网关关闭时自动停止挂机 |
| 自动重连 | 异常断线按指数退避重建登录服、角色网关和 Sproto 会话，成功后恢复调度；密钥材料仅以进程内 AES-GCM 密文保存 |
| 挂机调度 | Web 启动、停止、立即执行；按配置间隔串行执行，单项失败不阻断其他任务 |
| 挂机任务 | 角色/账号邮件、每日普通签到、午晚定时体力、已完成日常任务、50/100/150 活跃宝箱、指定副本扫荡 |
| 状态同步 | 捕获 `Role_RoleInfo` 与 `Task_DailyTask` 服务端推送；与请求回包同包时也不会丢失 |
| 状态记录 | 本地服务器记录最近命令、最近执行结果和事件日志 |

- 指定副本扫荡已经接入 `Battle_WipeOut`；实时战斗在“不改 MAS 客户端”的边界下不接入，除非服务端另行提供合法的模拟或离线战斗协议。

- 增加正式服执行队列，支持任务排队、暂停、恢复和失败重试。
- 增加操作日志导出和异常截图记录。

## 实时战斗可行性审计

实时战斗不能通过 Node 直接发送 `Battle_FinishFight` 实现。客户端真实链路为：

```text
Battle_CreateTeam
  → Battle_ReadyBattle
  → Battle_StartLoad
  → Unity 场景、角色属性和怪物初始化
  → Battle_FinishLoadScene
  → 固定帧战斗逻辑及必要的帧上传
  → Battle_FinishFight
  → Battle_AwardWin
```

`Assets/GamePlay/Hotfix/Battle/` 当前有 109 个 C# 文件，其中 93 个直接引用 `UnityEngine`，至少 53 个依赖 `GameObject`、`Transform`、`Physics`、`Animator` 等 Unity 运行时对象，无法直接链接到现有 .NET Sproto Bridge 中。客户端还明确对部分单人关卡启用帧数据上传验证，因此独立服务不能伪造胜利结果。

`D:\code\cad-client-mas` 仅允许只读分析，禁止由本工具修改、构建、注入或启动改造版客户端。因此实现范围固定为 Node/Sproto 执行器：登录、心跳、邮件、签到、任务、宝箱和服务端明确提供的 `Battle_WipeOut`。若后续需要实时战斗，必须先取得服务端正式提供的模拟战斗或离线战斗协议；在此之前不发送伪造结算，也不引入任何依赖 MAS 客户端改造的 Worker。
