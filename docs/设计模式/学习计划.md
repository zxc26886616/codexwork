# 设计模式学习计划

这份文档用于记录设计模式的学习路线、代码练习和实际应用。目标不是背诵模式名称，而是学会识别代码中的变化点，并选择足够简单的设计方案。

## 学习目标

- 理解常见设计模式解决的问题，而不只记住类图。
- 能说明一个模式的适用场景、代价和替代方案。
- 能用小型示例实现模式，并通过测试验证行为。
- 能把模式应用到游戏开发中的状态、技能、UI、事件和对象管理。

## 推荐路线

### 第一阶段：面向对象基础

- 封装、继承、多态。
- 组合优于继承。
- 单一职责、开闭原则、依赖倒置。
- 识别重复代码、过长方法和频繁变化的条件分支。

### 第二阶段：创建型模式

- 工厂方法：把对象创建交给子类或具体工厂。
- 抽象工厂：创建一组相互配套的对象。
- 建造者：分步骤构造复杂对象。
- 原型：通过复制已有对象创建新对象。
- 单例：保证全局只有一个实例，并认识其测试与耦合风险。

练习方向：敌人生成、道具配置、角色属性构建和游戏服务管理。

### 第三阶段：结构型模式

- 适配器：让不兼容的接口协同工作。
- 装饰器：在不修改原类的情况下叠加能力。
- 外观：为复杂子系统提供简单入口。
- 代理：控制对目标对象的访问。
- 组合：用统一方式处理单个对象和对象集合。

练习方向：第三方 SDK 接入、装备词条、资源加载入口和场景节点树。

### 第四阶段：行为型模式

- 策略：在运行时替换算法或行为。
- 状态：让对象的行为随内部状态变化。
- 观察者：在对象变化时通知多个订阅者。
- 命令：把操作封装成可排队、撤销或重放的对象。
- 责任链：让多个处理者依次尝试处理请求。
- 模板方法：固定流程骨架，把部分步骤交给子类实现。

练习方向：角色状态机、战斗 AI、事件系统、技能释放和输入回放。

## 每个模式的学习步骤

1. 先写出不用模式时遇到的具体问题。
2. 用一句话说明模式如何隔离变化。
3. 画出参与对象及它们的依赖关系。
4. 写一个最小示例并补充正常与异常测试。
5. 记录模式带来的复杂度以及不适合使用的场景。
6. 在已有项目中寻找真实用法，比较它与示例的差异。

## 和游戏开发的连接

- 状态模式：角色待机、移动、攻击、受击和死亡状态。
- 策略模式：敌人移动、选敌、攻击和掉落算法。
- 观察者模式：任务进度、UI 刷新和全局事件通知。
- 命令模式：技能释放、输入缓冲、撤销和战斗回放。
- 对象池：重复利用子弹、特效、敌人和列表项。
- 工厂模式：根据配置创建敌人、技能、道具和关卡元素。
- 组合模式：场景树、UI 节点和行为树。

## 当前行动

- 先学习策略模式、状态模式和观察者模式。
- 每个模式写一个独立小例子，并说明不用它时的代码问题。
- 每完成三个模式，选择一个小游戏功能进行组合练习。
- 如果模式只增加层级、没有隔离真实变化，就回退到更直接的实现。
