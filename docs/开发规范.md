# 开发规范

## 基本原则

- 先做可玩的最小版本，再加美术、音效和关卡。
- 保持入口简单，浏览器打开 `index.html` 应该能直接运行。
- 游戏逻辑、渲染、输入处理尽量分区清晰。
- 重要数值集中管理，方便调手感。

## 建议项目结构

```text
projects/
  game-name/
    README.md
    index.html
    styles.css
    game.js
    assets/
```

## 建议文件分工

| 文件 | 职责 |
| --- | --- |
| `index.html` | 页面结构、Canvas、按钮、HUD。 |
| `styles.css` | 页面布局、UI 样式、响应式适配。 |
| `game.js` | 游戏状态、输入、更新循环、碰撞、绘制。 |

## JavaScript 结构建议

- `createState()`：初始化游戏状态。
- `update(dt)`：更新游戏逻辑。
- `draw()`：绘制画面。
- `spawnXxx()`：生成敌人、道具、障碍。
- `collectAndCollide()`：处理收集和碰撞。
- `updateHud()`：同步界面数值。

## 验证清单

- `node --check game.js` 能通过。
- 开始、暂停、继续、重开按钮可用。
- 键盘输入可用。
- 移动端触控区域不遮挡核心画面。
- Canvas 首屏不是空白。
- 游戏结束后可以重新开始。

## Git 提交建议

提交信息可以使用简短中文：

```text
新增信号漂移原型
调整飞船移动手感
中文化游戏界面
补充游戏设计文档
```
