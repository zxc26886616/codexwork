# 百局批次监管

在项目根目录的 PowerShell 执行。审核人负责正式账号、只读预检、人工接管和独立记账。监管自身没有自动启动下一批的入口。

```powershell
$watch = 'evidence/2026-11-05-hundred/批次监管/监管.py'
$campaign = 'evidence/2026-11-05-hundred'

# 建票成功后使用其批次号。每条命令必须检查退出码；失败即停。
$ticket = python -B $watch prepare | ConvertFrom-Json
$batch = $ticket.batch
$pin = $ticket.pin
& "$campaign/大厅预检.ps1" -Batch $batch
python -B $watch allow $batch --pin $pin
python -B $watch start $batch
python -B $watch wait $batch --seconds 45
python -B $watch status $batch
```

start 返回独立后台监管进程的 PID。看到本批的 worker.json 才代表产品进程已经创建。wait 最多等待指定秒数，发现本地熔断、接管请求、退出或监管异常会提前返回。调度方应立即读 status 的 alert、handoff、verifyTable 和 officialEnded。后台进程不会弹系统窗口或通过聊天发消息。ownClock.seconds 是最近五秒内的合格己方棋钟采样，lastKnownSeconds / lastKnownAt 保存历史实读。clockEvidence.estimatedSeconds 是根据已验证截止时间推算的剩余秒数。

已发意图明确卡在界面锁五秒，或同一代次、阶段和意图连续五秒仍无服务端进展时，监管会检查原桌同席己方棋钟。新鲜采样不超过三十秒时，停排并给出接管提醒。采样中断但原程序记录了匹配的验证截止时间时，在估计剩余三十秒时停排并提示核实原桌。最新采样切为对手回合，或出现同一意图的服务端进展时，会取消此判断。

```powershell
# 紧急停排，保留既有匹配或席位。stopConfirmed=false 时继续观察或重试。
python -B $watch stop $batch

# 监管确已离线时使用。只重接观察、停排和归档。守护仍在时会因监视锁忙而退出。
python -B $watch recover $batch

# 监督退出并归档后，独立核对。以核对输出的累计结批。
python -B "$campaign/核对台账.py" $batch
$total = (Get-Content -Encoding utf8 -Raw "$campaign/百局台账.json" | ConvertFrom-Json).total
python -B $watch close $batch --audited-total $total
```

每批票据绑定前序、累计、单次批次号、完整清单 SHA256。正常批次额度为 min(3, 100-累计)。每批发车前要取得本批新放行，再次验证固定包、完整 P0 验收报告、累计、无正式占用和九十秒内的账号空桌预检。后台进程先取得监视锁，再启动独立看门进程，收到就绪后才派发该批唯一 worker。进程创建前即持久化消费和发车意图，断线以后没有补发路径。已有事故、救场、接管或审计不完整时，结批.json 可以记录结果，固定构建的熔断仍会阻止续排。

如果 E 已放行、尚未消费，但原预检超出 90 秒，E 可在该批目录保留原件并采新的只读大厅。新原始 JSONL 必须在原 E 放行后取得，且为同账号、同站点、空桌空队、无处罚、普通/即时/自动模式正常。E 将其写入唯一的 临启预检-<32位小写UUID>.json，字段与大厅预检.json 相同，checkedAt 取新原始 before.at。随后原子发布 E临启复核.json，decision 为 E_REFRESH_PREFLIGHT_ONLY，并填写 batch、pin、ticketSha256、allowSha256、originalPreflightSha256、preflightFile、preflightSha256 和实际 reviewedAt。不覆盖原预检，也不再调用 allow。

start 在消费时绑定当前 E 复核、新预检和原放行的 SHA256。后台守护在创建发车意图前、创建游戏进程前都要重验这些字节及原始采样的新鲜度。已消费的批号不能再次 start；消费后换凭证也不能让后台再次发车。

对于 allocated-play-seat-not-ready，产品负责验证同一官方桌已经开局、双方账号及双人即时制规则匹配、原桌尚未接席且已等待约八秒。监管再将事件与本批缓存的桌号、自己和对手交叉核对，一致时立即发布需接管.json。连续入口同时返回原桌号、ownClock（未读时为 null）及 officialEvidence，既不猜测剩余秒数，也无需等到三十秒低钟阈值。已知官方终局时抑制接管。证据冲突时停排并要求核对。allocated-table-progress-unresolved 保持原判断。

所有产品文件读取统一走 CreateFileW 并指定 FILE_SHARE_READ、FILE_SHARE_WRITE、FILE_SHARE_DELETE。Windows 上允许同时取得 DELETE 权限并重命名源文件。对仍被打开的目标做覆盖替换仍可能返回错误 5。读句柄短时打开后释放，状态变更以 mtime 检查，原包会重试符合条件的短暂状态快照冲突。遇到停排超时或存储故障时查看原包 .stop-queue 实物、监管异常.json 和进程状态。监督发出请求与产品实际确认停排分开记录。

归档位于 批次/<batch>/，包含本批 .json、.status.json、.log、.ends.jsonl、.incidents.jsonl、.fallback.jsonl、可用的 stop/hold 标记、同桌 matches、同席进展/棋钟及监督文件。异常退出时以同桌同账号官方终局区分已完桌与仍待核实原桌。若中断发生在 worker 创建与 PID 落盘之间，归档可能缺少单次启动或退出码证据，审核须保留该缺口。

主机重启导致原进程退出码未知时，唯一一条原 worker 启动记录和同 PID 的 recover/null 退出记录均须保留。若救场仅用原包对同一批同一张桌执行一次 --resume，并停在暂停交接，E 可在 断电原桌救场/E重启复核.json 绑定原票、放行、消费、原进程树、重启日志、原状态、救场意图与进程、停排、官方双方席位/终局及恢复退出原件的哈希。E 必须核实原树已丢失、救场已退出、没有重新排队。审核会区分原进程 PID 和救场 PID；原退出码保留 null，断档桌强制排除，整批不能记 clean。其他已有正常桌仍需独立核实在重启前完成。换版时再次核验同一 E 原件，并且仍须有原桌真实 P0、官方终局和已结批独立台账。

主机或 worker 真实退出、原桌仍在比赛时，由 E 使用原桌救场.py。传入实际批号和桌号，不传 --start 只检查；加 --start 时会重新执行全部检查。官方读数来自同桌公开接口，须确认 play、同两席和即时制条件。原批须已消费和停排，正式根、原包、原进程树退出、账号/批次锁释放及同桌未确认意图均须可核。命令只派发原固定包对该批的 --resume。资料目录中已有任何救场痕迹、原件冲突或占用不明时会拒绝。意图发布后无论是否取得 PID 均不能再次派发。该命令不安装后台任务，也不替代独立核账；进程受理与实际显示/动作仍要分别观察。

```powershell
python -B "$campaign/批次监管/原桌救场.py" $batch $table
python -B "$campaign/批次监管/原桌救场.py" $batch $table --start
```

监管按票据绑定的 E 换版记录选择 candidateId、完整 pin 和生产 EXE。发生新的游戏 P0 时会再次熔断。已关闭的原包、历代 E 验收、旧批和旧票据永久保留。

## 从桌 943447870 的事故换版

旧批 b86b83dbf7b64785a1e6e071a89df383 因 receipt-unresolved-after-authoritative-read 停排。官方正常终局 28:41，该桌经独立审核排除。结批时累计为 0。E 把结批时总账的原始副本存为 换版复核/<唯一新批号>/旧台账.json，并在同目录签发 E换版.json。换版程序分别固定旧事故25件归档的 SHA256、旧结批台账 SHA256、新旧 manifest SHA256 和新候选目录名。

E换版.json 的 decision 为 E_ALLOW_FIXED_UPGRADE，previous、batch、fromPin、pin、candidateId、previousArchiveSha256、previousLedgerSha256 和 reviewedAt 标识换版对象及时间。targeted 和 regression 各含相对项目根的 path 与 sha256。前者必须是该新包对原桌事故的通过报告，绑定底层证据。后者必须在同一新包上覆盖原 75 个不同的组名/用例，逐项通过并通过底层指纹校验。新包门槛独立于根目录保留的旧固定包验收.json。

首次换版时，将 E 已审核的批号赋给 $batch，用下列命令替换上面示例的普通 prepare，其余大厅预检、allow、start 和独立核账步骤相同。

```powershell
$ticket = python -B $watch prepare-after-upgrade $batch | ConvertFrom-Json
$pin = $ticket.pin
```

该原始换版只允许一张新三局票。后续正常结批后恢复普通 prepare，新票持续绑定同一换版记录的批号和 SHA256；旧事故继续留在排除表中。独立核账程序也重验换版依据。达到 100 局即停止，剩余不足三局时按余额建票。

从第二次换版开始，每条 E换版.json 还须包含 previousUpgradeBatch、previousUpgradeSha256、originalTable、incident。前两项取自发生新 P0 的旧票，后两项要与其事故记录、熔断和新包定向报告一致。监管从当前签核逐级回溯历史根，拒绝断链、历史样本改写、回用祖先 pin、仍在局中、缺少真实 P0、定向报告不符和原 75 项缺失。首批用原独立结批累计作为 baseline，永远单独发三局。剩余不足三局时不会越过上限尝试新产品。

## 已确认邀约后被平台撤桌

每次在独立目录 撤桌复核/<唯一新批号>/ 提供 E撤桌.json、结批原始字节的旧台账.json、独立官方撤桌.json，以及处置后从正式大厅入口新取的原账号大厅.jsonl。E 记录的 decision 为 E_ACCEPT_PRESTART_CANCEL，pin、previous、batch、table 绑定固定包、前批、新票和唯一撤桌，previousArchiveSha256、previousLedgerSha256、officialSha256、lobbySha256 绑定四份原件。lobbyRequestedUrl 为正式大厅入口，reviewedAt 记录实际审核时间。

恢复时要求原进程的邀约确认、分桌、终局与独立核账一致。官方结果须为 archive、cancelled=0、didntstart_players_left，双人桌无开局时间、无在席人数、无排名。该桌为唯一排除桌，没有出牌、回执、棋钟、兜底或其他 P0。运行时前批可能保留 queuePending 和 offerTable，所以还须最新独立后台账号采样证明没有进行中桌、排队或平台限制。签票时该采样有效期为 90 秒。

```powershell
python -B $watch prepare-after-cancel $batch
```

随后对新的批号再次执行大厅预检、allow、start 和独立核账。旧票、停排标记和排除记录留在原位；若前批已有经独立认可的正常样本，它们保留在累计。当前固定包在一张干净三局票通过先导验收之前，恢复票始终须能容下三局。此前不同批次的正常桌不能拼成首三。

监管观测到票面允许的最后一次入队时，在与产品相同的批次互斥锁内独占新建 .stop-queue，文件内容明确标识额度。这个闩允许已经在途的匹配到原桌完赛并保留产品的正常退出。出现额外入队、真正 P0、人工停排或接管时仍单独熔断。独立审核只有在全部局数正常、精确入队次数、额度文件和监督事件一致且没有其他停排原因时，才会将整批记为 clean。严格实时性取决于外部监管能及时观察到入队日志。

## 首批旧平台提醒的单次恢复

本节记录 94e8 的历史签发过程。现在只读复核其证据，1bf51 的启动入口禁止再签发旧包提醒恢复票。

首批 03a0f0ae33594a0ebdec0b70acf72326 仅在大厅碰到既有处罚提醒，零入队、零在途、零分桌、零局。原始事故唯一原因是 platform-penalty。精确提醒指向历史桌 942953060，账号 99769903，海盐折纸，11 月 5 日 10:57，名誉值 -20。该历史桌不进入本批桌数。监管将该次已审结的全部 22 个文件与旧总账固定为 SHA256，原批资料中多一个文件或改一个字节都会阻止恢复。

本次唯一候选新批号为 b86b83dbf7b64785a1e6e071a89df383。E 将正式账号独立采集的原件置于 处置复核/<新批号>/。监管只核验证据。

- 第一条沿用已固定指纹的 处置.jsonl 和 新会话大厅.jsonl。后续每条使用 处置-<桌号>.jsonl 和 新会话大厅-<桌号>.jsonl。每份处置均须看到正确账号、官方处罚页、唯一历史桌号、日期、既有名誉扣分和精确的“明白了！”按钮，以及一次真实点击。账号安全、主动承诺、其他限制或额外条款均会阻止恢复。
- 单页应用可以不发生顶层导航。此时要求处置后的页面明确变更，并由不同进程从正式大厅入口独立读到同一项后继提醒，下一条操作前再核对相同的桌号、日期和扣分。中间步骤退出码 5 只在这组证据吻合时接受。已处理的桌号不能重复，链内出现未处置的提醒时不能建票。
- 最后一次处置须正常退出，同实例在正常页面读到原账号，独立新实例的终点须为正式 /lobby。还要验证账号空桌、空队列、无提醒，普通、即时、自动模式和“海盐折纸 开始游戏”可用。
- E复核.json 的 decision 为 E_ACCEPT_NOTICE_CHAIN。previous、batch、pin、previousArchiveSha256 继续绑定旧批、唯一新批、固定包和已核22件旧档。lobbyRequestedUrl 为正式大厅地址，reviewedAt 是 E 最终实际复核时间。有序 steps 各含 table、actionSha256、lobbySha256、reviewedAt。支持 2 至 32 项逐条审查。实际三项依次为 942953060、942995174、943019322。
- 如果最终原始大厅采样已超过 90 秒，应将新的独立采集另存为 最新大厅复读.jsonl，并在 E复核.json 增加 refreshedLobbySha256。最新复读必须晚于最后一条独立读数、使用新的进程并满足同一空桌条件。建票时按最新大厅的实际采样时间计算 90 秒，原始步骤的证据与哈希始终保留。
